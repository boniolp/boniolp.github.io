Part 1 · kd-trees
Recall: kd-trees (see the slides)
  • Each node holds one point and a cutting dimension. The cutting dimension cycles as we go down the tree: x at the root, then y, then x again, and so on.
  • Going down, we compare a single coordinate: if the cutting dimension of node T is x, a point P goes to the left if $P_x < T_x$ and to the right otherwise.
  • Each subtree covers an axis-aligned bounding box BB. Every point of the subtree is inside its box, so the distance from Q to the box is a lower bound on the distance from Q to any point of the subtree.
  • Construction (strategy 2): the node is the median point of its subtree along the cutting dimension. Balanced, but slower to build than random splits (strategy 1).
Algorithm 1 NN(Q, T, cd, BB)
  1. ▷ Solution 2 of the slides: best-so-far (BSF) + pruning. best and best_dist are global; best_dist = +∞ at start
  2. if T = NULL or distance(Q, BB) > best_dist then return ▷ this box is too far: prune the whole subtree
  3. dist ← distance(Q, T.data)
  4. if dist < best_dist then best ← T.data ; best_dist ← dist ▷ new BSF
  5. if Q[cd] < T.data[cd] then ▷ visit the most promising side first
  6. NN(Q, T.left, (cd+1) % DIM, BB.trimLeft(cd, T.data))
  7. NN(Q, T.right, (cd+1) % DIM, BB.trimRight(cd, T.data))
  8. else
  9. NN(Q, T.right, (cd+1) % DIM, BB.trimRight(cd, T.data))
  10. NN(Q, T.left, (cd+1) % DIM, BB.trimLeft(cd, T.data))

Solution 1 (wrong): only go down the most promising branch, from the root to a leaf, and return the best point met on the way. There is no backtracking.

(d) Which prunings depend on the best-so-far?

  • D is at box distance 1.5. With the BSF of Solution 1 (2.06), we would have to visit it (1.5 < 2.06). It is pruned only because we found G (1.12) before reaching it. J (5.0) and B (3.04) would be pruned in both cases.
  • C and E were visited for nothing: their boxes are only 0.5 away from Q (they touch the line x = 6), while their points are far (4.61 and 1.80). The box distance is a lower bound, and here it is loose: the boxes are large, but the points inside are not where the box is closest to Q.
Take-away

Two things make the search fast: finding a good BSF early (visiting the most promising side first), and tight bounds. The order matters: the same algorithm with a bad visit order computes more distances, but still returns the exact answer.

Q2

kd-trees: Random Splits and High Dimensions

(a) Random splits. Strategy 1 splits the space at a random position instead of the median.

  • What is the height of a median-split kd-tree on n points, with leaves of b points? What is the worst-case height with random splits?
  • Consider the 1D dataset {1, 2, 3, 4, 5, 20}. A random split picks a value uniformly between the minimum and the maximum of the points in the node. What is the probability that the first split isolates 20 alone? And that it isolates 3 alone?
  • Use this to explain why random trees are a bad idea for search but a great idea for anomaly detection (Isolation Forest). Why do we build a forest and not a single tree?

(b) High dimensions. We build a median-split kd-tree on n = 20,000 points drawn uniformly in $[0,1]^d$, with leaves of b = 16 points (the cutting dimension cycles over the d dimensions).

  • What is the height of the tree? For d = 32, how many dimensions are cut at least once on a path from the root to a leaf? What does the bounding box of a leaf look like in the other dimensions?
  • Predict how the fraction of points whose distance is computed by Algorithm 1 changes when d goes from 2 to 128.

(c) The slides say that the complexity is O(log n) on average, but O(n) in the worst case. Using the Beyer theorem, explain why the pruning test of Algorithm 1 fails in high dimensions.

(a) Random splits: bad for search, good for anomalies

  • Height. A median split halves the number of points at each level, so the height is $\lceil \log_2(n/b) \rceil$. A random split can be very unbalanced: if every split cuts off a single point, the height becomes O(n), and a search may follow a path of length n. This is why strategy 1 is fast to build but "generates unbalanced trees".
  • Isolating 20. The cut is uniform in [1, 20], an interval of length 19. Any cut in (5, 20) isolates 20: probability 15/19 ≈ 0.79. Isolating 3 alone would need the cut to fall between 3 and itself on both sides at once, which is impossible: 3 has neighbours on both sides, so it needs at least two splits (probability 0 with one split). More generally, a point in a dense region needs many splits before it is alone.
  • Path length as a score. Outliers are isolated close to the root (short path), and normal points deep in the tree (long path). For search, an unbalanced tree is a problem. For anomaly detection, the depth at which a point is isolated is the anomaly score: the length of the path is a proxy for the density of the space, as in the slides.
  • Why a forest. One random tree is very noisy: a normal point can be isolated early by bad luck (with probability 4/19 the first cut falls in (1, 5), and the path of 20 gets longer). Averaging the path length over many independent trees reduces this variance. This is the idea of Isolation Forest (ICDM 2008).

(b) What happens in high dimensions

Height: $\lceil \log_2(20{,}000 / 16) \rceil = \lceil 10.3 \rceil = $ 11 levels, so a root-to-leaf path cuts at most 11 dimensions (one per level). For d = 32, at least 21 dimensions are never cut: in these dimensions the box of a leaf is the full interval [0, 1], and its contribution to $d(Q, \text{box})$ is 0. The box looks like a "slab" that is bounded in a few dimensions and infinite in the others, so it is close to every query.

We ran the exact search on such a tree (50 random queries) and measured the fraction of points whose distance is computed, together with the ratio $D_{max}/D_{min}$ between the farthest and the nearest point of a query (over 2,000 points):

(c) Why pruning fails: Beyer et al. (1999)

For many distributions (for example i.i.d. coordinates), when the dimension m grows:

$$\forall \epsilon > 0, \quad \lim_{m \to \infty} P\left[D_{max} \le (1+\epsilon) D_{min}\right] = 1$$

All points are at almost the same distance from Q (see the last row of the table). We prune a subtree T only if $d(Q, \mathcal{P}(T)) > d(BSF, Q)$. But $d(BSF, Q) \approx D_{min}(1+\epsilon)$, and the distance to a box is at most the distance to the farthest point, $d(Q, \mathcal{P}(T)) \le D_{max}$. So the test needs $D_{max} > (1+\epsilon) D_{min}$, which becomes impossible:

$$\lim_{m \to \infty} P\left[d(BSF, Q) < d(Q, \mathcal{P}(T))\right] = 0$$

Nothing is pruned, and the search visits all n points: O(n). On top of that, (b) shows that the boxes are not tight. Both effects get worse with d.

Important to note

What matters is the intrinsic dimension of the data, not d itself. Uniform random data is the worst case. Real data (time series, images) often lies close to a low-dimensional structure, and indexes still prune well. We will see this again with IVF in Q6.

Part 2 · SAX and iSAX
Recall: PAA, SAX and lower bounds
  • PAA: a series T of length n is cut into w segments of equal length, each replaced by its mean $\bar{x}_i$. The distance $DR(\bar{X}, \bar{Y}) = \sqrt{\frac{n}{w}}\sqrt{\sum_i (\bar{x}_i - \bar{y}_i)^2}$ is a lower bound of the Euclidean distance: $DR \le ED$.
  • SAX: each PAA value is replaced by a symbol. The breakpoints cut the values into |A| regions of equal probability under N(0,1) (series are z-normalized). For |A| = 4: $\beta_1 = -0.67$, $\beta_2 = 0$, $\beta_3 = 0.67$, and the symbols are a < b < c < d. Only the symbols are stored, so DR cannot be computed any more.
  • MINDIST uses a lookup table: $cell_{r,c} = 0$ if $|r - c| \le 1$, and $\beta_{\max(r,c)-1} - \beta_{\min(r,c)}$ otherwise. Then $MINDIST(\hat{X}, \hat{Y}) = \sqrt{\frac{n}{w}}\sqrt{\sum_i cell(\hat{x}_i, \hat{y}_i)^2}$, and $MINDIST \le DR \le ED$.
  • iSAX: the symbols are written in binary, and each symbol can be stored with fewer bits (a lower cardinality): with 3 bits, 110; with 2 bits, 11; with 1 bit, 1. Writing 1* means "the first bit is 1, the next bits are unknown".

So S becomes {101, 010, 011, 110}.

Why this is still a lower bound. A symbol with unknown bits is a range of symbols at the higher cardinality: 01 means "010 or 011", i.e. a range of values. To lower-bound the distance, we must take the value of that range that is closest to $T_i$:

  • if $T_i$ is inside the range (prefix case), the closest is $T_i$ itself: distance 0;
  • if the range is below $T_i$, the closest symbol is the largest one of the range: fill with 1s;
  • if the range is above $T_i$ (segment 2: 010–011 is above 000), the closest symbol is the smallest one: fill with 0s.

This is the same idea as MINDIST to a bounding rectangle: a word with unknown bits is an envelope, and we measure the distance to the closest point of the envelope.

(b) Insertions

  • t1 = {01,11,10}: at the root, its 1-bit word is {0*,1*,1*}: internal node. Then {01,1*,1*}: internal. Then {01,11,1*}: a leaf with 4 series. Room left: it now holds 5.
  • t2 = {01,10,11}: same path down to the leaf {01,10,1*}, which is full (10/10). We split it. Segments 1 and 2 are already at the maximum cardinality (2 bits), so the only possible split is on segment 3: 1* becomes 10 or 11. The leaf becomes an internal node with two children: {01,10,10} (5 series) and {01,10,11} (5 series + t2 = 6).
  • t3 = {10,01,00}: at the root, its 1-bit word is {1*,0*,0*}. No child of the root has this word, so we create a new leaf under the root, with 1 series (lines 21–24 of the insertion code).
  • t4 = {00,11,01}: 1-bit word {0*,1*,0*}: a leaf with 7 series, now 8.

If all 10 series were {01,10,11}: the split puts all 11 series in {01,10,11} and none in {01,10,10}. The new leaf is still overflowing, and it cannot be split again, because all symbols are at the maximum cardinality. This is the case SplitNode() == false in the slides: the series is inserted anyway, and the leaf exceeds its capacity. In practice, we use a large maximum cardinality (8 bits per symbol, |A| = 256), so that this only happens for (nearly) identical series. Note also that iSAX trees are not balanced, and a split can produce a very unbalanced pair of leaves.

1. Approximate search. Follow the word of the query: Root → {0*,1*,1*} → {01,1*,1*} → {01,10,1*} → L3 = {01,10,11}. We read L3 and return its closest series: ED = 2.0. This is an ng-approximate answer: fast, but without any guarantee.

3. Depth-first, left to right. BSF = 2.0 after reading L3.

  • L1: 2.6 ≥ 2.0, pruned.
  • {0*,1*,1*} (0) → L2: 1.8 < 2.0, read: closest at 1.9 → BSF = 1.9.
  • {01,1*,1*} → {01,10,1*} → L3 (already read) and L4 (0.4): read → BSF = 1.5. Then L5 (0.9): read, no improvement.

Leaves read: L3, L2, L4, L5: one more disk access than best-first. L2 was read only because the good leaf L4 had not been found yet. As in the kd-tree (Q1), the answer is the same and exact in both cases; only the cost changes. Visiting by increasing lower bound finds a good BSF early, which is why the slides (and the DTW index) use a priority queue.

4. Monotone MINDIST. A child refines its parent: it has the same symbols with more known bits, so it represents a subset of the series (a smaller envelope). The closest point of a smaller envelope cannot be closer: $MINDIST(Q, \text{parent}) \le MINDIST(Q, \text{child})$. This is what makes it safe to prune a whole subtree as soon as its root is too far. On the path of the query, every node contains the word of the query itself, so the query is inside the envelope and the MINDIST is 0.
