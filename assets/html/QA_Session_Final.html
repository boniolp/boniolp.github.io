Lecture 1 · Information retrieval and the Web
Q1

MinHash

Lecture 1

Two documents are represented by their sets of shingles: A = {s1, s2, s3, s4, s5, s6} and B = {s4, s5, s6, s7, s8, s9}. We estimate their Jaccard similarity with MinHash, using k = 100 independent hash functions: the estimate is the fraction of hash functions for which the minimum hash value of A equals that of B. Which statement is correct?

  • AThe minimum is taken over the union A ∪ B, not over A: the element of A ∪ B with the smallest hash is equally likely to be any of the 9 elements of the union.
  • BThis divides by |A| + |B| = 12, which counts the 3 shared shingles twice. The Jaccard similarity divides by the size of the union, 9.
  • CCorrect. The two minima are equal if and only if the element of A ∪ B with the smallest hash is in A ∩ B: probability 3/9 = 1/3. Each hash function gives a Bernoulli variable of mean J, so the average over k functions is unbiased, with variance J(1−J)/k = (1/3)(2/3)/100, i.e. a standard deviation of about 0.047.
  • DThe expectation of each indicator is exactly J, so the average is unbiased for any k; only its variance decreases with k. The estimator that is biased is the one obtained by randomly sampling k shingles from each document (Lecture 1 Q&A).
Q2

PageRank without Repairing Dangling Nodes

Lecture 1

Consider a 3-page web graph with the links A → B, A → C and B → C. Page C has no outgoing link. We iterate $\pi \leftarrow G\pi$, where G is the column-normalised transition matrix ($G_{ij} = 1/\deg^+(j)$ if $j \to i$), without repairing the dangling node and without damping, starting from $\pi = (1/3, 1/3, 1/3)$. What happens?

  • AIt is a tempting intuition, but C has no outgoing link, so the column of C in G is all zeros: the mass that reaches C is not sent anywhere at the next step. C cannot keep it.
  • BCorrect. π₁ = (0, 1/6, 1/2) (sum 2/3), π₂ = (0, 0, 1/6) (sum 1/6), π₃ = (0, 0, 0). G is not column-stochastic because of the zero column of C, so probability mass leaks out. This is why we replace the column of a dangling node by a uniform distribution, and add the damping term $(1-d)U$: then $M = d\tilde{G} + (1-d)U$ is column-stochastic and π stays a probability vector.
  • COscillations can happen with periodic graphs (for example A → B → A) when there is no damping. Here there is no cycle, and the mass simply disappears.
  • DA receives no link, so its score drops to 0 after the first iteration: π is not uniform after one step.
Lecture 2 · From hardware to databases
Q3

Disk Scheduling

Lecture 2

A disk has tracks 0 to 199. The head is on track 50 and moving towards higher tracks. The queue holds requests for the tracks 82, 17, 43, 140, 24, 16, 190 (in their order of arrival). We compare FCFS (order of arrival), SSTF (shortest seek time first: always the closest request) and SCAN (the elevator: go up to the last track, then come back down). Which statement is correct?

  • ACorrect. FCFS: 32 + 65 + 26 + 97 + 116 + 8 + 174 = 518. SSTF serves 43, 24, 17, 16, then 82, 140, 190: 7 + 19 + 7 + 1 + 66 + 58 + 50 = 208. SCAN goes up 50 → 82 → 140 → 190 → 199 (149 tracks), then down to 16 (183 tracks): 332. SSTF is greedy: a request far from the head is skipped as long as closer requests keep arriving (starvation, as in the Lecture 2 Q&A). SCAN serves every request on the current or the next sweep.
  • BSSTF is a greedy choice: it is optimal on this example, but not on every sequence (always taking the closest request can lead the head far away and force a long trip back). And above all, it can starve requests, so it is not used as it is.
  • CSCAN goes to the end of the disk (track 199) even though the last request is at 190, and comes back: 332 tracks, more than SSTF here. Its advantage is fairness, not the total distance.
  • DFCFS is indeed starvation-free, but so is SCAN: a request is always served during the current or the next sweep.
Q4

Where to Put the Parity Blocks?

Lecture 2

Data blocks B1–B12 are spread round-robin on 4 disks, as below. Parity group i covers 3 consecutive blocks: $P_1 = B_1 \oplus B_2 \oplus B_3$, $P_2 = B_4 \oplus B_5 \oplus B_6$, $P_3 = B_7 \oplus B_8 \oplus B_9$, $P_4 = B_{10} \oplus B_{11} \oplus B_{12}$. A lost block can be rebuilt from the other blocks of its group and the parity, as long as only one of them is lost.

Disk 1Disk 2Disk 3Disk 4
Row 1B1B2B3B4
Row 2B5B6B7B8
Row 3B9B10B11B12

Which placement of (P1, P2, P3, P4) allows us to recover from the failure of any single disk?

  • AP1 is on disk 1, which also holds B1, a block of group 1. If disk 1 fails, we lose both B1 and P1 and cannot rebuild B1.
  • BGroup 2 is B4, B5, B6, and B4 is on disk 4: losing disk 4 loses both B4 and P2. (A dedicated parity disk also becomes a write bottleneck, since every write updates it.)
  • CGroup 2 is on disks 4, 1, 2 (B4, B5, B6): P2 on disk 1 shares the disk with B5.
  • DCorrect. The parity of a group must be on the only disk that holds no block of that group. Group 1 is on disks 1, 2, 3 → P1 on disk 4. Group 2 on disks 4, 1, 2 → P2 on disk 3. Group 3 (B7, B8, B9) on disks 3, 4, 1 → P3 on disk 2. Group 4 (B10, B11, B12) on disks 2, 3, 4 → P4 on disk 1. The parity is also spread over all disks, as in RAID 5.
Lecture 3 · Database systems
Q5

Normalising to 3NF

Lecture 3

The relation Teaching(sid, course, teacher, office) records, for each student and course, the teacher of the student in that course and the office of the teacher. The functional dependencies are {sid, course} → teacher and teacher → office. The key is {sid, course}. Which statement is correct?

  • Aoffice depends on the key only through teacher (sid, course → teacher → office): this is a transitive dependency, which 3NF forbids. In practice, the office of a teacher is repeated for every student, and updating it in one row but not the others creates an inconsistency.
  • BCorrect. The common attribute, teacher, is a key of R2, so joining R1 and R2 gives back exactly the original relation (lossless). R1 has the key {sid, course} and R2 the key teacher, and no transitive dependency is left. Both dependencies are also preserved.
  • CThe common attribute is office, which is not a key of either relation: two teachers can share an office, and the join creates spurious tuples. The link between a student and their teacher is also lost.
  • DThis decomposition assumes that course → teacher, which is not given: two students of the same course can have different teachers (for example, different groups). The join on course creates spurious tuples.
Q6

Durability: Which Order?

Lecture 3

A client sends UPDATE accounts SET balance = 80 WHERE id = 2; COMMIT; to a DBMS. The figure shows the components involved and the operations between them, and the table describes each operation.

StepOperation
querythe client sends the SQL query
fetchlook up the page in the buffer pool; if it is not there, read it from the database files
modifyapply the change to the page in the buffer pool and mark it dirty
logappend the change record <T, page, old=50, new=80> to the log
commitappend <T, COMMIT> to the log and flush the log to disk (fsync)
okreturn "OK" to the client
writewrite the dirty page to the database files
checkpointwrite a checkpoint record in the log

Which order guarantees both durability (once the client gets "OK", the update survives a crash) and atomicity (a crash never leaves a half-done transaction that cannot be undone)?

  • AThe client is told "OK" before the commit record is on disk. If the machine crashes right after, recovery finds no COMMIT record for T and undoes it: a transaction confirmed to the client is lost. Durability is broken.
  • BThe page is written to the database files before the log record that describes it. If the machine crashes between write and log, the disk holds an uncommitted value and the log does not know the old value (50): recovery cannot undo the change. This violates the write-ahead logging rule, and atomicity is broken.
  • CThis is the same problem as A, with a window of up to one second: every transaction acknowledged during the last second before a crash is lost. Some systems offer this mode (asynchronous commit) for speed, but then they explicitly give up durability.
  • DCorrect. Two rules are enough. (1) Write-ahead: the log record of a change is on disk before the page itself (here, the fsync of commit flushes log too, and write comes later). (2) Commit before acknowledging: commit (with its fsync) happens before ok. The dirty page can then be written later, in the background and in batches: after a crash, the log is enough to redo it. The checkpoint bounds the part of the log that recovery must replay.
Lecture 4 · Graph databases
Q7

Finding a Path: Relational vs. Graph Database

Lecture 4

The railway network of the Lecture 3 Q&A has about 3 000 stations and N = 150 000 connections: rows of a table Hop(src, dst) in a relational database (recursive query, B+tree index on Hop.src), or relationships between Station nodes in a graph database (index-free adjacency). We look for a path from Rennes to Strasbourg with a breadth-first search that ends up traversing m connections, with m ≪ N. What is the cost of this search in each system?

  • ACorrect. With index-free adjacency, a node stores direct references to its relationships: following a connection costs O(1), whatever the size of the graph, so the search only pays for the part of the graph it explores. In the relational database, each step of the recursion looks up the neighbours of the frontier stations in the B+tree on Hop.src, which costs O(log N) per lookup. Both systems answer the question; the graph database is a better fit for traversals.
  • BPlain relational algebra cannot express reachability, but SQL has recursive queries (WITH RECURSIVE) since SQL:1999. As discussed in the Lecture 3 Q&A, it is a question of fit and cost, not of expressiveness.
  • CThis swaps the two costs. Index-free adjacency means precisely that the graph database does not go through a global index to find the neighbours of a node, while the relational database does.
  • DNeither system needs to touch the whole graph: a breadth-first search only explores m connections. And with an index, the recursive query never builds the Nk product of k joins: each step only looks up the neighbours of the current frontier.
Lecture 5 · Indexing: B+trees and hashing
Q8

B+tree and Sorted Inserts

Lecture 5

We insert the keys 1, 2, 3, …, 1 000 000 in increasing order into an empty B+tree, using the standard split: when a leaf overflows, half of its keys move to a new leaf. What does the tree look like at the end?

  • AThe split moves half of the keys to the new leaf. With sorted inserts, every new key goes to the last leaf: the left half of each split is never touched again, so it stays half full.
  • BA B+tree is always balanced: every split pushes a key up, and the tree only grows at the root. All leaves stay at the same depth, whatever the order of the inserts.
  • CCorrect. Every split leaves a half-full leaf behind, and no key will ever be inserted into it again. The tree uses about twice the space it needs. This is why bulk loading (sort, then fill the leaves completely) or a split policy adapted to sorted inserts (for example, moving only the new key to the new leaf) is used for this case.
  • DThe height is $O(\log_f n)$ for a fan-out f, whatever the order of insertion, since the tree stays balanced. Only the space usage suffers.
Q9

Adding a Server

Lecture 5

Keys are distributed over 10 servers. We add an 11th server. Approximately what fraction of the keys must move to a different server, (i) with modulo hashing (server = h(k) mod N), and (ii) with consistent hashing?

  • AWith modulo hashing, changing N changes the server of almost every key, not only the keys of the new server.
  • BThe fraction is much larger than 1/2: see D.
  • CThis is right for modulo hashing, but consistent hashing only moves the keys between the new server and its predecessor on the ring.
  • DCorrect. (i) A key stays on its server only if h(k) mod 10 = h(k) mod 11. Over a block of lcm(10, 11) = 110 consecutive values, this happens for 10 values (0 to 9), i.e. 1/11 of the keys: 10/11 of the keys move. (ii) With consistent hashing, servers and keys are placed on the same ring, and each key goes to the next server clockwise. The new server only takes the keys of one arc, about 1/11 of the keys if the servers are evenly spread (which virtual nodes help to achieve). This is the minimum possible, since the new server must end up with its share of the keys.
Lecture 6 · Time series similarity
Q10

Computing DTW

Lecture 6

Let X = (x1, …, xn) and Y = (y1, …, ym) be two time series of different lengths (n ≠ m). A warping path W is a sequence of pairs (i, j) that starts at (1, 1), ends at (n, m), and moves at each step by (1, 0), (0, 1) or (1, 1). The DTW distance is

$$DTW(X, Y) = \min_{W} \sqrt{\sum_{(i,j) \in W} (x_i - y_j)^2}$$

We only need the value of DTW(X, Y), not the alignment itself. What are the time and the memory needed by the best exact algorithm?

  • AA warping path has at most n + m − 1 pairs, but we do not know which path is optimal: the best path can go through any cell (i, j), so all n·m cells must be considered. (Enumerating the paths themselves is even worse: their number is exponential in n and m.)
  • BCorrect. Let D(i, j) be the best cost of a path from (1, 1) to (i, j). Every path to (i, j) arrives from (i−1, j), (i, j−1) or (i−1, j−1), so $D(i,j) = (x_i - y_j)^2 + \min(D(i-1,j), D(i,j-1), D(i-1,j-1))$, and DTW = √D(n, m). Each of the n·m cells is computed once, in O(1). Row i only uses row i − 1, so two rows of length min(n, m) are enough to get the distance.
  • CThe time is right, but the full n × m matrix is only needed to recover the alignment (by backtracking). For the distance alone, two rows are enough. With n = m = 105, this is the difference between 80 GB and 1.6 MB of float64.
  • DDTW does not need series of the same length: a point of one series can be matched with several points of the other. This is one of its advantages over the Euclidean distance.
Q11

Which Lower Bound for DTW?

Lecture 6

To speed up a DTW search, we prune candidates with a cheap lower bound of DTW: LB_Kim (built on a few features such as the first, last, minimum and maximum values), LB_Yi (the parts of the candidate above the maximum or below the minimum of the query), or LB_Keogh (the parts of the candidate outside the envelope U, L of the query). The DTW we compute is the general (unconstrained) DTW, with no warping window. Which statement is correct?

  • ACorrect. The envelope is $U_i = \max(q_{i-r}, \dots, q_{i+r})$ and $L_i = \min(q_{i-r}, \dots, q_{i+r})$, where r is the warping window. With no constraint, the window covers the whole series, so U and L become the global maximum and minimum of Q, and LB_Keogh only counts the parts of C above max Q or below min Q: this is LB_Yi. The strength of LB_Keogh comes from a narrow envelope, i.e. a Sakoe-Chiba (or Itakura) band. For general DTW, it loses its advantage.
  • BThis is true with a narrow warping window, where the envelope follows Q closely. Without a window, the envelope is flat and LB_Keogh brings nothing more than LB_Yi (see A).
  • CLB_Kim only uses 4 numbers per series, so it is very loose. It is used as a first, very cheap filter in a cascade of bounds, not as the tightest one.
  • DLB_Keogh remains valid with r = n: it is just loose. Every point of each series must be matched with at least one point of the other, and that is all these bounds need.
Lecture 7 · Indexing for similarity search
Q12

kd-trees in High Dimensions

Lecture 7

We build a median-split kd-tree on n = 106 vectors drawn uniformly in $[0,1]^{128}$, with leaves of 32 vectors, and run the exact nearest-neighbour search of the course (best-so-far + pruning with the distance to the bounding boxes). Which statement is correct?

  • ABalance makes a single root-to-leaf path short ($\lceil\log_2(10^6/32)\rceil = 15$ levels), but the cost of the exact search depends on how many subtrees are pruned, and in high dimension almost none are.
  • BCorrect. With 15 levels, at most 15 dimensions are cut on a path: in the other 113, a leaf box covers the whole range and contributes 0 to the distance to the box. And by the Beyer theorem, $D_{max} \approx D_{min}$ in high dimension, so the pruning test d(BSF, Q) < d(Q, box) almost never succeeds. The search degenerates into a serial scan, plus the overhead of the tree.
  • CThe algorithm is still exact: it only prunes a subtree when its lower bound proves that the subtree cannot contain a better point. In high dimensions it is slow, not wrong.
  • DIt is the opposite: each split only uses one coordinate out of 128, so the cells get worse as the dimension grows.
Q13

Choosing nlist in IVF

Lecture 7

We index n = 106 vectors of dimension d = 128 with IVF, and search with nprobe = 1. With balanced cells, the cost of a query (in multiply-adds) is $n_{list} \cdot d + \frac{n_{probe}}{n_{list}} \cdot n \cdot d$. Which statement is correct?

  • AThen the scan is cheap, but ranking the centroids costs $n_{list} \cdot d = n \cdot d$: exactly the cost of a serial scan.
  • BWith 20 cells, each cell holds 50 000 vectors: the scan costs about $5 \times 10^4 \times 128 = 6.4 \times 10^6$, 25 times more than the optimum.
  • CCorrect. The derivative of the cost is $d - \frac{n_{probe}\, n\, d}{n_{list}^2}$, which is zero for $n_{list} = \sqrt{n_{probe} \cdot n} = 1000$. Then both terms are equal (128 000 each), for a total of 256 000, versus $n \cdot d = 1.28 \times 10^8$ for a serial scan. This is the $O(\sqrt{n} \cdot d)$ cost of the course.
  • Dnlist changes both terms of the cost: more cells mean more centroids to rank, but smaller cells to scan. It also changes the recall (smaller cells mean more neighbours across the borders), which is why nlist and nprobe are tuned together.
Lecture 8 · Graph-based search: from small worlds to HNSW
Q14

Navigable Small Worlds: Kleinberg

Lecture 8

We build a graph on an n × n grid. Each node is linked to its 4 grid neighbours, and receives one extra long-range link, built in one of the ways below. Messages are then routed with a decentralised greedy algorithm: each node only knows the grid coordinates of the target and its own links, and forwards the message to the link closest to the target (in grid distance). According to Kleinberg's theorem, which construction lets greedy routing deliver any message in an expected number of steps that is polylogarithmic, $O(\log^2 n)$?

  • AUniform links give a small diameter: short paths exist. But they are spread uniformly over the grid, so once the message is close to the target, almost no link helps it get closer. Kleinberg shows that any decentralised algorithm then needs at least of the order of $n^{2/3}$ steps: the short paths exist, but cannot be found with local information.
  • BThe exponent 1 is still smaller than the dimension of the grid (2): links are still too long on average, with the same problem as A. The expected delivery time is polynomial, of the order of $n^{(2-r)/3} = n^{1/3}$.
  • CCorrect. With exponent r = 2, equal to the dimension of the grid, the links are spread evenly over all scales: from any node, the probability of having a link into the next "ball" twice as close to the target is about the same at every distance. Each such halving takes O(log n) steps in expectation, and there are O(log n) scales, hence $O(\log^2 n)$. For any other exponent, the time is polynomial in n. This is the idea that NSW and HNSW build on: a graph with links at every scale can be navigated greedily.
  • DWithout long-range links, every step only moves the message by at most 3 cells: a route between two far nodes takes Θ(n) steps (of the order of the grid distance divided by 3).
Q15

Greedy Search in a Proximity Graph

Lecture 8

In a navigable small world graph (NSW), the search starts from an entry point and moves greedily: at each step, it goes to the neighbour closest to the query, and stops when no neighbour is closer than the current node. In the graph below, the search starts at E. The number next to each node is its distance to the query q.

Which node does the greedy search return?

  • ACorrect. From E (9.22), the neighbours are A (6.40) and B (5.83): go to B. From B, the neighbours are E, A and C (4.12): go to C. C has no neighbour closer than itself: stop. The true nearest neighbour, N (1.41), is only reachable through A and D, which the greedy search left behind at the first step. This is why graph search is approximate. In practice, the search keeps a list of the ef best candidates instead of a single one (beam search): here, with ef = 3, A stays in the list, and the search later explores A → D → N and finds the nearest neighbour.
  • BConnectivity guarantees that N can be reached, not that a greedy walk reaches it: the walk only follows edges that bring it closer to q, and can get stuck in a local minimum.
  • CAt the first step, greedy search compares A (6.40) and B (5.83) and goes to B, the closest. It never goes through A.
  • DThe search does not stop at the first improvement: it continues as long as a neighbour is closer than the current node, so it goes on from B to C.
Q16

The Hierarchy of HNSW

Lecture 8

In HNSW (Malkov & Yashunin), each new vector gets a maximum layer $l = \lfloor -\ln(u) \cdot m_L \rfloor$, with u uniform in (0, 1], and is inserted in all layers from l down to 0. With the usual setting $m_L = 1/\ln(M)$ and M = 16, we insert n = 106 vectors. Which statement is correct?

  • AOnly layer 0 contains all the vectors. The upper layers contain fewer and fewer vectors, which is what makes them fast to cross.
  • BThis would be the case with a probability of 1/2 per layer (as in a skip list with p = 1/2). Here, $P(l \ge 1) = P(u \le e^{-1/m_L}) = e^{-\ln 16} = 1/16$.
  • CThe upper layers are subsets of the vectors themselves, chosen at random by the level formula. There is no clustering.
  • DCorrect. $P(l \ge k) = e^{-k/m_L} = 16^{-k}$. For $10^6$ vectors: about 62 500 in layer 1, 3 900 in layer 2, 244 in layer 3, 15 in layer 4 and about 1 in layer 5. The search starts from the entry point at the top, moves greedily within each layer, and uses the node it reaches as the entry point of the layer below. The upper layers act as "express lanes" with long links: the search gets close to the query in a few steps before refining in the dense layer 0 (with a beam of size ef). This gives a number of steps that grows roughly like log n, and avoids getting stuck in local minima far from the query, as in the previous question.
